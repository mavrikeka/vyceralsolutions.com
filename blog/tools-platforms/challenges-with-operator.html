Challenges with Operator

January 28, 2025 • 3 min read • GenAI in GTM

Yesterday I had written about my initial response in working with OpenAI Operator. Here is a link to that article. It was fascinating and scary at the same time. I was seeing a new way of things getting done and my initial reaction was amazement.

For some context, I had asked Operator to build me a Tableau Dashboard, build me an Agent.ai agent and build me a Clay table. You can see all the Operator videos by clicking into the links. Specifically I was quite impressed with the Agent.ai agent that it built. I would say that it got 80% of the way there and that was impressive.

So where my brain immediately went was - "I should be able to train this to get to 100%". Again I am always looking for real use cases and real applications of technology. While it is fun to play around with them and hype them up, if it doesn't solve real business problems, I don't make any money. So I spent all of yesterday and today trying to get Operator to get to generate an agent. The reality is that if it can get to 80% there is no reason it cannot get to 100%. It shows that it can do the job and all that it needed help with were a few specifics.

So I did what every good manager does, I gave it much more detailed and specific instructions. I even asked it to take my instructions to ChatGPT and have ChatGPT generate instructions that a CUA (Computer User Aided) application like Operator would understand. It was a good hypothesis.

Here is a detailed write up about my experiment -

The bottomline is that I could not figure out a way to get it to 100%. The more instructions I gave it the dumber it got. This is so counter-intuitive, because when we work with humans who can do a job 80% well we give them a few tips, show them where they got stuck and they can get to 100%.

In fact, as I became very specific and detailed everything out, the things that it could do earlier, it started forgetting how to do.

The other part that was surprising was that it did not learn and get better. I had thought that if I gave it the same task, 3 times, this was AI and every time it would learn and remember. The way Operator works today, it does not seem to have any memory. So all the training I did and all the instructions I gave it while it was doing the job, when I asked it to do that job again, as a new task, it has no memory. So it is like training someone and they come back the next day and they start from scratch. Also, I can't give it simpler instructions once I have given it complicated instructions, in case there is a limitation that it's memory only lasts for the session it is in.

One thing about playing around with Operator is that it shows not just where the Use Interface of the application is not intuitive but also where the way the application works is not intuitive.

As an example, in Agent.ai if my input is the name and company of an executive and I want to find the LinkedIn URL, I have to do a search result but the search result brings back other text in addition to the LinkedIn URL and the activity that finds the LinkedIn profile needs a LinkedIn URL and that is a very specific format and so you cannot just search for the LinkedIn URL and pass the search results to the Find LinkedIn profile action, you have to do some clean up. Operator could just not figure this out.

So bottomline, without even getting into the bigger flaw about how the screenshot technology works, there are some serious issues with this being anything more than a toy currently.
