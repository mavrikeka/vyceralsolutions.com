Everyone is a programmer - Part 2

January 14, 2025 • 4 min read • GenAI in GTM

A month ago I had posted about my experience working with ChatGPT to build a tax optimizer application with GPT o1 pro, that replaces me needing an expert tax person to do tax strategy (I will still need them to file my taxes) - https://lnkd.in/efqnFHYA. It was worth the $200. It actually works and has real logic and calculations. That experience was eye opening.

I was not sure if it was going to be a one off experience or if this was going to be something I do regularly.

A back story on what I've been doing this last year. I started my consulting firm back in Feb 2024 and at that point, all I knew was that I wanted to get deep into GenAI by applying it to a domain I had expertise in - GTM. Within a week I realized that ChatGPT, Co-pilot, AI assistants, Custom GPTs were not going to be very helpful. There is only so much one can do with LLM data. With no access to web search, tools to access data from other systems, ability to upload documents and use them as a data source - the use cases were non-existent.

This led me down the path of agents and agentic workflows and evaluating and working with many agent building tools. Initially my work was more around GTM consulting but over time I transitioned and now I primarily do GenAI in GTM and GenAI in general. There are a few tools that I now have in my arsenal that I use regularly - AnyQuest, Agent.ai, Clay.com and I am always looking at Agent builders that are low-code/no-code and targeted at business stakeholders.

I've built 100s of agents, some for clients, most to learn and some to teach others. What becomes very obvious is that the use cases you can tackle depend on the data you have access to which in turn is dependent on the tools the agent builders give you access to. For example, here are the sources Agent.ai can pull data from -

Meanwhile Clay being a GTM focused tool has a gazillion integrations - https://www.clay.com/integrations. AnyQuest has the ability to add any tool that one wants via PyAQ (e.g. Apollo etc.).

Considering that all these products have so many choices when it comes to integrations, I had never thought about the need to build my own integration and anytime I had a use case that needed a different integration, I'd stay away from it or do that part of the process manually.

That being said, each of these tools has the ability to add more integrations via a Web API and other options that requires programming. So naturally I put this under the too hard to solve bucket and moved on to other use cases.

Till I started playing around with ChatGPT and had it generate code. The other day I had a simple use case. I was building a newsletter agent - you give me your email and a topic of your interest and I will store that in a Google Sheet and then I will have another agent that reads from the Google Sheet, loads the email and topic into a list and then uses an LLM to find the latest news about the topic and then emails you back the results.

The only challenge was that Agent.ai did not have a Google Sheet integration. It had an email integration and I was having people submit their email address and topic and I would get an email and then I would manually add this to my Google Sheet. Then I would download the CSV and feed it to my agent to do the rest of the work. This was still a pretty fast workflow and automating something that in the past I could never have done. So I was willing to live with a little inefficiency.

So first thing about everyone being a programmer, this is a program. We might call it an agent but I built something that took some input, stored in, did some processing and returned a useful output.

The second thing was that I decided to see if I could expose the data in my Google Sheet as a Web API and then call that Web API from my agent and eliminate the 2 manual steps. So I went to ChatGPT and it gave me step by step instructions and the code to go do this. I deployed the code and then it told me how to test the code and then told me what parameters to pass to Agent.ai and soon I had my integration working.

Here is a video for those that are interested - https://youtu.be/hxXO0VOU3Kg

What I have realized is that being comfortable taking on tasks that require a Web App, Web API, Python code, Node.js etc. without actually having to write the code is extremely liberating and powerful. To be fair these are small snippets of code and not full blown applications but still, it does open my agentic workflows to a whole new set of use cases.

I am very excited to see what 2025 brings!!!
