GenAI - Will we see a new application architecture?

Created on 2024-10-22 09:20

Published on 2024-10-22 14:00

Almost a year ago I started my own consulting firm focusing on GenAI because I had a hypothesis that GenAI would fundamentally transform Go-To-Market (GTM). I did not know how it would transform GTM or whether it would actually transform GTM, but my simple 'follow the money logic' was that if 100s of billions of dollars were being spent at the LLM layer, this would have to translate into trillions of dollars of value and a lot of the value would come from a new type of application built with a GenAI first approach.

If we look back at the evolution of software (my intent is not to be exhaustive here but to paint a picture) - Mainframe -> Client Server -> Web -> SaaS (private cloud) -> Public Cloud -> GenAI?

There have been big shifts that led to new types of applications being built and new market leaders being created. The way applications were built fundamentally changed and this led to incumbents being disrupted and new leaders being created.

IBM (mainframe) -> Microsoft/Oracle/SAP (Client Server) -> Google/Amazon (Web) -> Salesforce/Workday (SaaS) -> AWS/Azure/Google (Public Cloud) -> OpenAI/Anthropic (GenAI).

Are we on the cusp of something similar with GenAI? Will the way we fundamentally build applications in a new way that will disrupt the current SaaS architecture. If we look at a SaaS application like Salesforce and break it down into it's core components - It was built for humans and it had a UI for users to enter data, it had a repository that became the system of record (schema), it had workflows for users to do their job, it had analytics and it integrated via an API to other systems.

GenAI has the ability to disrupt this architecture in a few ways -

  1. Can GenAI replace data entry? Can it automatically capture information and update systems of record without humans having to manually do this? Humans don't like data entry and we've already see this play out in eCommerce. You buy something on Amazon and there is a whole process from order to cash to shipping that is now done digitally. Can something like this happen to B2B SaaS applications? The challenge is where is the source data coming from that will feed this data entry and it looks like initially it is going to be emails and calls. Here are a couple articles from Andreesen Horowitz that talks about this and applications looking to address this.

2. Is there a new type of architecture that combines search, analytics, data entry, workflow and are there any companies that are built this way from the ground up? I recently was sent the keynote video from www.devrev.ai from their annual customer conference where they showcased their product and what they call SaaS 2.0. Now DevRev is focused on the post-sale journey (Support) but the concepts are similar. Take a lot of the structured and unstructured data and build a system that organizes it, understands it, cleans it up, routes it to right human or agent, updates other systems of record and provides conversational search and analytics.

3. When I was at Gong, the founders always had this vision that Gong would be the new Salesforce. We had access to a data set that no one else was tapping into (Calls and Emails) and we knew what was really going on in the sales process as the calls and emails had all that information. Let's say we were working with a small startup that did not have a CRM and they gave us access to all the calls and emails, would we not be able to intuit which account we were working with and then go to the web / a data provider and create an account object? Could we not create a contact record based on the calendar invite / email / call transcript and then enhance this with LinkedIn data? Based on the conversation could we not figure out if there was an opportunity or if this was a prospect? Could we not create an opportunity record and know what stage it was at based on the conversations? We know what objections / buying signals / when someone is tire kicking / we know MEDDIC and how we are proceeding down a sales cycle. So what stops Gong from building a new system of record that sits alongside Salesforce today (and maybe replace it)? Andreesen Horowitz has another interesting article about how AI startups can sit alongside incumbents and start by feeding them data but eventually siphon them off.

There is one big challenge - incomplete data. We saw this at Gong. If you do not have all the customer interactions (not all calls are recorded, text / whatsapp messages are not captured) it gave an incomplete picture. Is there no new opportunity at the prospect because we have not had any conversations or is it because we did not record the conversations. I think there are ways to get around this - A calendar invite will tell us if there is a meeting, there are email threads that can give context and maybe there is a way to capture meeting notes instead of call recordings? Maybe over time people get more comfortable capturing all interactions?

Bottomline - When there is a tectonic shift, incumbents are in danger. We saw this with Microsoft and their struggles from 200X to 2014. We saw this with Oracle from 201X - 2020s. Now these companies have cash cows and money, so they can wait for the next architecture revolution to come about. Microsoft did this with Cloud and GenAI. Oracle is reinventing itself as we speak. But it does not change the fact that their legacy architectures were problematic for them and we will see this with traditional SaaS incumbents - IF GenAI ends up with a new architecture.
